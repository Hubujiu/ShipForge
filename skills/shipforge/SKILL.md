# ShipForge

Use `assistant.open` on the member's first visit and `assistant.history` for read-only access. Start with `assistant.send` and a nonempty body. Pass a previous room ID to continue and supply a stable request ID on retries. Follow the returned space and room ID to read `chat.history`. A private assistant uses its member's available Runtime. To change a group avatar, read `chat.avatar` for its revision, then run `shipforge --space SPACE group-avatar CHAT PATH --rev REV` or send `chat.avatar.set` with that revision. An owner can clear it with `remove: true`. [Assistant, groups and membership](../../docs/conversations.md)

Read `machine.storage.preview` for the selected machine. Queue a fresh scan with `machine.storage.request`, then poll the preview. For an owner-confirmed cleanup, pass one returned workspace ID and its expected snapshot with `confirm: true`. A conflict or protected workspace requires a new preview. Machine-only calls `machine.storage.take`, `machine.storage.reserve` and `machine.storage.finish` hold the cleanup reservation. Read `agent.runtime.options` before choosing an advertised model or reasoning effort. `run.enqueue` accepts a one-run override. Machine-local environment values belong in the worker's profile.

Read `network.settings` for the current device. Use `network.test` to check an unsaved proxy configuration and `network.save` with the current revision to apply a requested change. Keep proxy sign-in details in their dedicated fields. `device.about` returns the installed version and local guide, and `device.update` checks the stable release. These commands work independently of the project database. [Device connectivity](../../docs/device-network.md)

Use `status.library` and `task_type.workflow` to resolve organization definitions, local identities, type order and defaults before updating a task workflow. An organization administrator can create or revise definitions with `status.library.save`. A space administrator can save the ordered selection with `task_type.workflow.save`, the type revision and explicit `{"library":"…"}` references. Local IDs can differ from library IDs in upgraded spaces. To remove a status, inspect `status.library.removal` with the intended replacement, then submit its fingerprint to `status.library.remove`. A conflict requires a fresh preview. [Organization statuses and migration examples](../../docs/status-workflows.md)

Read `machine.runtimes` for the selected machine before acting. Its owner may request one advertised tool action with `machine.runtime.request` and a stable request ID. Poll the inventory for the final outcome. A model connection test sends one prompt. Install and upgrade invoke the machine's local package definition. For local supervisor management use `shipforge-worker service status|configure|start|stop|restart` with the intended data directory and machine configuration. The stop and restart operations interrupt active runs. Worker-only operations `machine.runtime.publish`, `machine.runtime.jobs`, `machine.runtime.finish` and `machine.stopped` authenticate as the machine.

Use `git.settings` with the chosen organization, space or Agent level to read Git repository bindings, author inheritance and the current revision. Save the requested scope and full replacement settings with `git.configure`. An optional `checkout_branch` on `run.enqueue` takes precedence for the execution. The worker uses its machine Git credentials to fetch and create worktrees. [Git workspace examples](../../docs/git-workspaces.md)

Use `organization.ownership` with the selected target and the requested grant, transfer or revoke action. Use `space.transfer` for an existing member of a specific child space, with that space's revision.

Read the signed-in person's `delivery.history` for work notifications, or use `invitations:true` as an organization administrator. Use `delivery.open` on an activity link to read its authorized destination. An accepted receipt confirms that the configured mail service accepted the message. Use `delivery.retry` for an explicitly rejected delivery. [Email and workspace links](../../docs/inbox.md)

Read `organization.settings` before changing shared defaults. An administrator can save `default_language` or `priority_levels` with `organization.configure` and the current revision. A member can explicitly leave a selected organization with `organization.depart`. For an owner-requested dissolution confirm the exact organization name, member count and current revision. Existing tasks retain their priority after the organization changes its offered levels.

Use `directory.people` with a member category and an optional query to disambiguate people, Agents, crews or machines by space and ID. Use `search` with `search_scope:"organization"` for objects across joined spaces. Open a direct conversation or create a group with `chat.start`, providing the selected space, mode, target or group members and a stable request ID. Re-read the destination with the current identity before opening it.

Use `catalog.install`, `catalog.update` and `catalog.uninstall` to manage the current space’s installation. Create an independent Agent with `catalog.instantiate`. Use `skill.import` to copy files, directories, ZIP packages or supported public GitHub URLs and `skill.bind` to bind an existing skill. Preserve each result's space and ID, including when names match. `agent.organize` changes the caller's pin or favorite. Use `profiles.list` to identify saved team accounts on this device, `profiles.use` to switch to a saved ID, and `profiles.forget` to remove its local sign-in. `profiles.remember` records the active account's space, page and optional record IDs. When sign-in expires, `shipforge connect <server> --account <id> --token-stdin` reauthenticates the same identity. [Account operations](../../docs/cli.md)

Read the caller's conversations with `chat.sidebar` and a room's chronological visible turns with `chat.history`. To organize just this member's list, use `chat.organize` with `pin`, `unpin`, `hide` or `undo`. Pass the token returned by `hide` as `undo_token` when undoing. A new visible turn restores the hidden room. Use `chat.fork` with the source room ID and `message` to branch through that turn. Continue by passing the new room ID and `body` to `chat.send`. For owners, `chat.bind_task` links an existing task by its ID, while `chat.convert` queues an Agent request to create and link a new task. Pass a stable `request_id` for retries and inspect the returned run for completion. [Conversation examples](../../docs/conversations.md)

Use `shipforge schema` for the request schema shipped with the running version, and `shipforge --version` to identify that version. The installed manual explains each operation and its inputs. [CLI manual](../../docs/cli.md) · [JSON Schema](../../docs/protocol.schema.json)

Read the current workspace and task before making a change. Use the space and object IDs returned by the API. Send UTF-8 JSON to `shipforge request` on stdin or through `--file`. Successful replies contain `ok: true` and `data`. Surface the error code and message when a command fails. On Windows, invoke `.\shipforge.exe` when running from the program directory.

Include the current `expected_rev` on updates and deletes. For ordinary record writes, retry with the same `request_id` and original body. A conflict calls for reading the current state before applying changes. The local and team identities share permission checks with the desktop client.

Use `iteration.timeline` to read the visible iterations with planning phase, task totals and capacity. Supply an optional `as_of` date in `YYYY-MM-DD` format. Before closing an iteration, inspect `iteration.preview`, then choose the open destination iteration or return remaining tasks to the backlog with `iteration.close`.

Read `iteration.settings` to identify the space's iteration mode, time zone and revision. For an authorized schedule change, send `iteration.configure` with a partial `fields` object and the returned `expected_rev`. Automatic mode uses an IANA zone, an anchor date, 1–8 weeks per cycle, cooldown days and a count of future periods. Auto-join tracks status and due-date changes within the relevant window. Use `iteration.start` for a manual start or to bring the next automatic period forward. In manual mode, filter the timeline with `owner:"@me"`. Use `iteration.history` to inspect the visible closure snapshot. Disabling the module ends started periods, removes unstarted ones and keeps historical scope. [Iteration policy and examples](../../docs/iterations.md)

Use `shipforge upload` and `shipforge download` for files. The equivalent protocol operations are `attachment.upload` and `attachment.download`. Each file can be up to 4 MiB. Downloads check the SHA-256 and preserve existing destination files. For a historical document attachment, pass its revision with `--version`.

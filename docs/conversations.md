# 对话成员、提醒与分享

## 个人小助手

在「我的任务」下方选择「小助手」。每个组织为当前成员保存一个系统助手，首次进入只创建助手。输入问题后点「发送」才会保存会话并排队。再次点侧栏「小助手」会清空编辑器。「最近对话」可打开之前的消息。名称和指令由系统管理，个人助手仅用于单独对话。[HiFox 系统助手](https://help.hifox.com/docs/agent-and-computer/agents) · [参考产品的最近对话行为](https://help.hifox.com/changelog)

编辑区的 Runtime 按钮可以选择本人在线工作机上的运行时，并可填写模型。新会话优先使用当前空间中符合条件的工作机，也可以在同组织的其他可写空间中执行。组织内切换空间会保留历史。继续旧会话时，运行时须在该会话原执行空间在线。离开私有空间后，来自该空间的历史、运行和结果随权限一同收回。只读令牌可查看自己已有的历史。

任务详情的「与处理人对话」使用任务当前指派的 Agent 或小队。每位成员有自己的任务会话。工作机获得该成员有权限读取的任务描述与评论。组织助手、自建个人 Agent、真人私聊和任务会话各自保留其成员范围。

## 群头像

群主在群详情选择「更换群头像」，浏览本地文件后确认。支持 2 MiB 以内的 PNG、JPEG、GIF 和 WebP，宽高最多 4096 像素。程序居中裁剪并保存 128 × 128 的 PNG，再生成 32 × 32 的列表头像。相同图片重复上传会保留原版本。当前成员可以在群详情和侧栏看到头像。移出群或群被解散后，图片接口同步收回访问。群主可通过「管理成员」转让群主，新群主可以更换或移除头像。

## 整理我的对话

在左侧栏悬停对话可选「不显示」，右键或「…」可以置顶或取消置顶。「对话」页也有这些操作。置顶项始终留在侧栏。隐藏后，当前成员的列表移除这一项并取消置顶，提示条提供「撤销」。撤销会恢复该项原先的置顶位置。成员各自的设置独立保存，重新打开项目仍然有效。任务对话列出本人发起或亲自发言的会话，自动化发起的任务会话在本人第一次发言后进入列表。

只要该对话产生自己有权读取的新消息，就会再次出现在最近对话中。编辑旧消息、另一间对话收到消息均不会恢复它。隐藏保留聊天历史、提醒设置和任务状态，仍可通过关联任务进入对话。 [HiFox 对话列表更新](https://help.hifox.com/changelog/2026-11-13)

## 从某条消息分叉

打开普通 Agent 对话或任务的 Agent 对话，在任一条本人可见的人类发言或 Agent 回复下选择「从此消息分叉」。新分支复制截至该条发言的历史，含该条消息，继承可见的 Agent 和任务关联。分支最初只对创建者开放，之后的发言分别留在各自的对话。清除源历史或失去源会话访问权限后，分支中的继承消息、附件和引用这些消息的 Agent 回复与产物也会从该成员的视图中消失。 [HiFox 对话说明](https://help.hifox.com/docs/agent-and-computer/chat-with-agent)

```json
{"op":"chat.fork","id":"analysis","message":"second-reply","request_id":"branch-analysis-1"}
```

## 把对话关联到任务

对话所有者可在普通 Agent 对话顶部选择「绑定到已有任务」，按名称或编号搜索自己可编辑的任务，再选择搜索结果。原对话和任务详情会出现互相打开的入口。要从当前讨论生成新任务，选择「将对话转为任务」。建单指令会出现在该对话，Agent 正忙时继续排队。可以离开页面，稍后回到对话查看结果。工作机成功返回任务草稿后，系统创建任务并绑定原对话。运行失败或草稿无效时，运行记录会显示处理结果。 [HiFox 对话与任务绑定](https://help.hifox.com/docs/agent-and-computer/chat-with-agent)

```json
{"op":"chat.bind_task","id":"design-review","task":"task-42","request_id":"bind-design-review"}
{"op":"chat.convert","id":"analysis","request_id":"create-task-from-analysis"}
```

在 Windows 的「对话」页新建普通对话或群聊。群主可从详情里的「管理成员」和「管理 Agent」添加或移出成员。修改名称、描述使用编辑对话。群成员可退出，群主可转让或解散。解散后成员无法继续查看该群的消息、产物和链接。有关联运行仍在执行时，先处理运行。

## 私有会话与群聊

所有请求可指定 `space`，默认是 `default`。创建私有群聊的示例为 `{"op":"create","kind":"chat","id":"review","title":"发布评审","fields":{"chat_type":"group","visibility":"private"}}`。普通对话使用 `chat_type:"conversation"`。之前创建的普通对话继续使用已有记录。

| 当前行为 | JSON 操作与所需身份 |
| --- | --- |
| 查看本人可见的对话管理信息 | `{"op":"chat.info","id":"review"}` 返回所有者、本人是否为所有者及提醒偏好。群成员可见当前成员和有权查看的 Agent。私有会话的授权详情和待接受名单由所有者查看。 |
| 管理群成员或 Agent | 群主发送 `{"op":"chat.manage","id":"review","action":"add","target":"bob"}`。移出用 `remove`。Agent 要增加 `"target_kind":"agent"`。 |
| 转让或离群 | `transfer` 的 `target` 为有编辑权限的空间成员。新群主须已经入群，普通私有会话可直接转让。旧所有者保留参与资格，直到退出或新所有者移出。普通成员用 `leave`，群主可选 `dissolve`。 |
| 邀请参与私有会话 | 能参与对话的成员发送 `invite` 和目标成员 ID。收件人读取 `{"op":"chat.invitations"}`，用 `{"op":"chat.manage","id":"review","action":"accept"}` 接受，或用 `decline` 拒绝。邀请接受前只显示邀请人和标题。 |
| 撤回访问 | 私有会话所有者发送 `revoke` 和成员 ID。私有任务会话同时检查任务可见性。消息、附件、产物、通知及其搜索结果随当前权限过滤。团队客户端断线时也要求重新连接以打开这些对象。 |
| 只清理本人历史 | `{"op":"chat.manage","id":"review","action":"clear","request_id":"clear-review-once"}`。当前历史从该成员的视图移除，其他成员仍可读取。此后收到的新消息正常显示。 |
| 提醒和免打扰 | `{"op":"chat.preferences","id":"review","muted":true,"ignore_all":true}` 改变本人设置。发送消息时在 `fields.mentions` 填成员 ID 数组，群聊可加 `mention_all:true`。直接提及本人会穿透免打扰与群体提及过滤。 |

## 选择内容与撤销分享

所有者在对话详情选择「分享已选消息」，逐条选择内容和范围。内容按原始消息顺序保存。关联工作机的回复只有在运行完成后才能分享。每次可选择 1 至 100 条消息，快照上限为 1 MiB，包括发言人显示名、Markdown 正文及附件文件名。可复制文本、复制链接或生成包含图片附件缩略图的 PNG。[图片与权限](conversation-commands.md)

```json
{"op":"chat.share.create","id":"review","message_ids":["first","answer"],"scope":"organization","request_id":"share-review"}
```

默认范围 `organization` 要求读取时仍有该组织的成员身份。显式选择 `link` 后，拿到链接的人可访问快照。后续讨论和编辑不会改变快照内容。团队 CLI 与桌面返回配置的团队服务地址加 `/share/<分享码>`。在浏览器打开持链可读的分享可直接读取纯文本。组织内分享请在已连接的桌面「对话 → 打开分享链接」粘贴链接，或使用认证 CLI。HTTP 客户端可向同一端点发送成员的 Bearer 令牌。本机模式用户可在同一工作区粘贴分享码。

```json
{"op":"chat.share.read","share":"替换为64位分享码"}
{"op":"chat.share.revoke","id":"review","share":"替换为64位分享码"}
```

「撤销此选区的分享」会使指向同一批消息的所有有效快照链接同时失效。另一批消息的快照单独管理。撤回会话成员的实时访问、撤销冻结的快照分别有独立的操作入口。

## 隔离环境复验

1. 用安装所有者在临时团队服务创建 A、B、C 三个普通成员，分别用个人写令牌连接独立的客户端配置。
2. A 创建私有会话并上传消息附件，邀请 B。B 在接受前尝试读取附件，接受后再读取。A 撤回 B 的访问后，再检查直接读取、附件下载、搜索与事件记录。
3. A 创建群组，加入 B 和 C。B 开启免打扰及忽略群体提及。A 依次发送普通消息、群体提及、直接提及 B。B 应仅收到最后一条通知。B 清理个人历史后，让 C 打开相同的历史消息，然后再发送一条新消息。
4. A 为同一批消息分别创建组织范围和持链可读的分享。无凭据打开前者应要求身份验证，组织外身份会被拒绝。A 编辑消息，再次打开已生成的链接应保留原文。撤销后两个入口都应返回不存在。
